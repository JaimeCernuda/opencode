# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Development Setup

**Requirements:**
- Bun 1.3 or higher
- Golang 1.24.x (for TUI)

**Start development:**
```bash
bun install
bun dev
```

This runs the main OpenCode server at `packages/opencode/src/index.ts`.

## Common Commands

### Development
```bash
# Run OpenCode locally
bun dev

# Run from specific package
cd packages/opencode && bun dev

# Type checking across all packages
bun typecheck        # or: bun turbo typecheck

# Run tests
cd packages/opencode && bun test
```

### Building
```bash
# Build all packages (respects turbo dependency graph)
bun turbo build

# Build specific package
cd packages/opencode && bun run build
```

### TUI Development
The TUI is written in Go and located in `packages/tui/`:
```bash
cd packages/tui
go build ./cmd/opencode
```

## Architecture Overview

OpenCode is a client/server AI coding agent with a modular architecture:

### Core Components

**packages/opencode** - Main server and CLI
- Entry point: `src/index.ts` (Yargs-based CLI)
- HTTP server: `src/server/server.ts` (Hono REST API)
- Session management: `src/session/` (immutable, versioned sessions)
- Agent orchestration: `src/agent/` (build, general, plan agents)
- Provider abstraction: `src/provider/` (multi-provider AI support)
- Tool registry: `src/tool/` (read, write, bash, grep, glob, etc.)
- LSP integration: `src/lsp/` (language server protocol support)

**packages/tui** - Terminal UI (Go/Bubbletea)
- HTTP client that connects to OpenCode server
- Handles user input and rendering
- Streams server-sent events (SSE) for real-time updates

**packages/sdk/js** - Auto-generated API client
- Generated by Stainless SDK generator from server.ts schemas
- **Important**: After modifying `packages/opencode/src/server/server.ts`, request SDK regeneration from OpenCode team

**packages/console** - Web-based console (separate SolidJS app)

**packages/web** - Documentation/landing page

**packages/plugin** - Plugin system for extensibility

**packages/function** - Cloudflare Workers/serverless functions

### Client/Server Architecture

The server can run in multiple modes:
- `opencode serve` - Headless HTTP server
- `opencode tui` - Launches server + spawns TUI client
- `opencode run` - Direct execution

All clients communicate via:
- REST API (Hono-based HTTP/1.1)
- Server-Sent Events (SSE) for streaming updates
- Configurable server URL via `OPENCODE_SERVER` env var

### Key Architectural Patterns

**Immutable Sessions**
- Sessions are versioned snapshots stored in hierarchical key-value storage
- Updates create new versions, enabling branching and reverting
- Storage paths: `["session", projectID, sessionID]`, `["message", sessionID, messageID]`, etc.

**Message Processing Flow**
1. User sends prompt → `POST /session/:id/message`
2. `SessionPrompt.prompt()` creates user message
3. Agent selects AI model and loads tools
4. `streamText()` from ai-sdk streams response
5. Stream events processed into parts (text, tool calls, reasoning)
6. Events published to Bus for real-time client updates
7. Tool results fed back to AI for agentic loops

**Provider Agnostic**
- Supports Anthropic, OpenAI, Google, AWS Bedrock, Azure, etc.
- Uses Vercel's `ai` SDK for unified interface
- Custom loaders for provider-specific handling
- Dynamic SDK loading via Bun's package installer

**Tool System**
- Registry of executable tools with JSON schemas
- AI generates tool calls, system executes them
- Results streamed back to AI for multi-step workflows
- Permission system for sensitive operations (edit, bash, webfetch)

**LSP Integration**
- Spawns language servers per project root
- Routes operations by file extension
- Provides diagnostics, hover info, symbol search
- Configurable via `config.lsp`

**Instance Pattern**
- Per-request context for project/directory state
- `Instance.provide()` wraps middleware
- Cleanup handlers for resource disposal

**Event Bus**
- Type-safe event publishing using Zod schemas
- Events: `session.updated`, `message.updated`, `message.part.updated`, etc.
- Powers SSE streams to clients

## Coding Style (from AGENTS.md)

- Keep code in single functions unless composable/reusable
- DO NOT unnecessarily destructure variables
- DO NOT use `else` statements unless necessary
- AVOID `try`/`catch` where possible
- AVOID using `any` type
- AVOID `let` statements
- PREFER single-word variable names where possible
- Use Bun APIs extensively (e.g., `Bun.file()`)
- ALWAYS use parallel tool calls when applicable

## Monorepo Structure

This is a Bun workspace monorepo managed by Turbo:
- `packages/*` - All packages
- `packages/console/*` - Nested console packages
- `packages/sdk/js` - SDK package
- Shared dependencies in workspace catalog (see root `package.json`)

## Important Notes

- **No core feature PRs accepted** - Only bug fixes, LLM improvements, provider support, env fixes, missing behavior, and docs
- **Commit style** - Study recent commits (`git log`) to match the repository's commit message conventions
- **API changes** - Server API changes require SDK regeneration by OpenCode team
- **Plugin hooks** - Available at: `chat.params`, `tool.execute.before/after`, `chat.message`
- **Single-step thinking** - Agent uses `stepCountIs(1)` for one agentic step per call
